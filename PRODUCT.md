# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated: dependency-light static web application for GitHub Pages with translation JSON kept separate from the interface code.

## Users

Potential clients and collaborators evaluating Hugo Menz for automation, AI workflow and application work. They may arrive through a proposal and need to understand the work without technical background.

## Product Purpose

Present five inspectable case studies with real application screenshots, guided demos, repository links, end-to-end flows and a concise scope note beside each project.

## Positioning

The portfolio proves work through inspectable applications and workflows. Menz RFQ Copilot is the principal case, Second Brain combines a useful note product with RAG security, FridgeFlow is the user-facing product, Agent Chaos Lab is the multi-agent experiment with Observatory as its runtime surface, and Music School shows enquiry automation.

## Operating Context

Visitors scan the five cases on the home route, inspect implementation detail on `/workflows/`, review the delivery method on `/approach/`, and switch between Spanish, English and German without losing their route. GitHub Pages is the public deployment target.

## Capabilities and Constraints

- All five projects use real screenshots captured from the current local builds.
- Translations live in separate `src/i18n/*.json` files.
- Commercial results, customers, metrics and production-readiness are not claimed.
- External integrations that require credentials are explained in a short project-specific demo scope note.
- High-level diagrams open in a native zoom dialog. They never send visitors to an external design tool.
- A scroll-aware section index remains available after the header leaves the first viewport.

## Evidence on Hand

Evidence consists of the five repositories, deployed demos, local build/test output, real screenshots and architecture documentation. There are no approved testimonials or customer metrics.

## Product Principles

- Show the application before explaining it.
- Explain the product first, then state public-demo boundaries once in plain language.
- Use ordinary language before implementation details.
- Keep the principal action visible: open the demo or inspect the repository.
- Explain workflow purpose and boundaries before listing nodes or services.
