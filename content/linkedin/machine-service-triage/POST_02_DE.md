# Entwurf 2 — Machine Service Triage

**Status:** Lokal, nicht veröffentlicht

Diese Demo nennt bewusst keine Fehlerursache.

Der Testfall enthält eine Schutztürmeldung nach einem mechanischen Umbau. Die Produktion steht. Anhänge fehlen.

Eine vermeintlich „smarte“ Automatisierung könnte aus Fehlercode und Historie eine Diagnose formulieren. Das wäre hier die falsche Aufgabe.

Der Workflow macht stattdessen Folgendes:

1. Sicherheitsbezug erkennen,
2. Priorität auf manuelle Eskalation setzen,
3. Ferndiagnose ausdrücklich sperren,
4. Maschinendaten und vorhandene Evidenz zeigen,
5. fehlende Informationen nachfordern,
6. einen Ticketentwurf vorbereiten.

Das Ergebnis ist „Zur manuellen Prüfung“. Kein Lösungsvorschlag, der wie eine technische Freigabe klingt.

Gerade im Maschinenservice ist ein guter Stop-Mechanismus oft glaubwürdiger als ein beeindruckender Happy Path.

Welche Meldung müsste in Ihrem Serviceprozess immer sofort eskalieren?
